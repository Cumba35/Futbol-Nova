**Fecha:** 19-11-2026  
**Proyecto:** Godot 4.4.1 · Android ARM64 · modo local/offline  
**Prioridad funcional:** amistoso local 11 contra 11.

## Resultado de la ejecución 334

La ejecución [44549563484](https://github.com/Cumba35/Futbol-Nova/actions/runs/44549563484) terminó en `failure`. Las pruebas principales del hub, base 11v11, amistoso en vivo con goles y períodos, vuelo del balón, marcos y redes de portería, catálogo/geometry de estadios, perfil de Máximo Padilla, acceso NOVA, política de recursos y smoke test Android finalizaron antes de la exportación.

El único paso que detuvo esta ejecución fue **Export arm64 debug APK**. Godot informó:

- `Cannot export project with preset "Android" due to configuration errors`.
- `Project export for preset "Android" failed`.

El APK no fue generado y el artefacto `futbol-nova-android-debug` no fue publicado. Las regresiones extendidas quedaron omitidas por la detención anterior.

## Causa técnica identificada

El workflow instalaba Java 17 y Android SDK, y descargaba las plantillas de exportación correspondientes a Godot 4.4.1. Sin embargo, no configuraba en los ajustes globales del editor Godot las rutas que Android export necesita:

- `export/android/java_sdk_path`
- `export/android/android_sdk_path`

Godot documenta estas rutas en la guía oficial de exportación Android 4.4: https://docs.godotengine.org/en/4.4/tutorials/export/exporting_for_android.html

La configuración se guarda en el archivo de ajustes del editor correspondiente a Godot 4.4: `~/.config/godot/editor_settings-4.4.tres`.

## Corrección aplicada

Commit de distribución: `fb024313eb48571695cc912e12da9eee00e28751`.

Se añadió el paso **Configure Godot Android export SDK paths** inmediatamente después de instalar la llave de depuración. El paso:

1. Comprueba que Java 17, Android SDK Platform Tools y el keystore existen.
2. Escribe `editor_settings-4.4.tres` con las rutas de Java y Android SDK del runner.
3. Registra también la ruta, alias y contraseña del keystore temporal de depuración.
4. Mantiene la selección ARM64 y el flujo de pruebas existentes.

No se guardan llaves privadas ni contraseñas permanentes en el repositorio; el keystore y sus credenciales siguen siendo temporales del runner.
